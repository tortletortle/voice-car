# 协议参考（公开资料，待本板 HEX 核实）

CI1302 是芯片；**模块出厂固件决定 UART 帧**。本车按亚博 Voice-ASR-TTS，优先方案 **Y**。

---

## Y. 亚博 Voice-ASR-TTS（本车优先）

来源：[教程](https://www.yahboom.com/study/Voice-ASR-TTS)、[命令表介绍](https://www.yahboom.net/public/upload/upload-html/1762853904/1.%20Introduction%20of%20voice%20module.html)、[交互控制](https://www.yahboom.net/public/upload/upload-html/1763370976/Voice%20interaction%20control.html)。

| 项 | 值 |
|---|---|
| 波特率 | **115200 8N1** |
| 帧 | 5 字节：`AA 55 <mode> <cmd> FB` |
| 常见 mode | `00` 主动/识别上报；`FF`/`01` 等被动播报（以 Excel 为准） |
| 帧尾 | 固定 **`FB`** |

例（出厂英文车控，**须本板抓包核实**）：

| 说法 / 事件 | 帧 |
|---|---|
| HI-YAHBOOM 唤醒 | `AA 55 03 00 FB` |
| Car Stop | `AA 55 00 01 FB` |
| Car Forward | `AA 55 00 04 FB` |
| Car Backward | `AA 55 00 05 FB` |
| Turn Left | `AA 55 00 06 FB` |
| Turn Right | `AA 55 00 07 FB` |

唤醒词出厂常见：`Hi, Yahboom` 或中文 `小亚小亚`（以固件为准）。

**本仓 `voice_uart` 仍为方案 A，发声通过后改为方案 Y。**

## A. M5 Module ASR 风格（对照，非本车）

| 项 | 值 |
|---|---|
| 识别上报 | `AA 55 ID 55 AA` |
| 唤醒例 | Hi, M Five → `AA 55 FF 55 AA` |

---

## B. 启英泰伦 CI130X UART Protocol V1（长帧，对照）

头 `A5 FA` … 尾 `FB`。见 Chipintelli 文档。STC8H 桥接后对外通常已是方案 Y，不必对主控再解长帧。

---

## C. 如何判定

对着串口 HEX：

1. `AA 55 ?? ?? FB` → **方案 Y（亚博）**  
2. `AA 55 ?? 55 AA` → 方案 A（M5）  
3. `A5 FA … FB` → 方案 B  

与车控帧区分：ESP→STM32 是 **`AA 55 CMD LEN SEQ CHK`（6 字节）**，见 `cmd_protocol.h`。
