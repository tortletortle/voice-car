# 语音小车 V1.0 语音指令规范

本文件定义语音识别层、ESP32 命令路由层与 STM32 执行层之间的统一指令语义。语音短语先归一化为一个命令，再使用现有六字节串口帧发送。

## 1. 语音指令表

| 用户说法 | 可接受的常用说法 | 规范命令 | 行为 |
|---|---|---|---|
| 前进 | 前进、向前走、往前走 | `CMD_FWD` | 小车向前 |
| 后退 | 后退、向后走、往后走 | `CMD_BACK` | 小车向后 |
| 左转 | 左转、向左转 | `CMD_LEFT` | 小车左转 |
| 右转 | 右转、向右转 | `CMD_RIGHT` | 小车右转 |
| 停止 | 停止、停下、刹车、别动 | `CMD_STOP` | 立即停止底盘运动 |
| 点头 | 点头、点一下头 | `CMD_GIMBAL_NOD` | 点头一次 |
| 摇头 | 摇头、摇一下头 | `CMD_GIMBAL_SHAKE` | 左右摇头一次 |
| 连续点头 | 点两下头、连续点头 | `CMD_GIMBAL_NOD_TWICE` | 连续点头两次 |
| 连续摇头 | 摇两下头、连续摇头 | `CMD_GIMBAL_SHAKE_TWICE` | 连续摇头两次 |
| 回正 | 回正、头部回正 | `CMD_GIMBAL_NEUTRAL` | 停止 Yaw，并将 Pitch 设为中位 |
| 打招呼 | 打招呼、你好 | `CMD_GIMBAL_GREETING` | 连续点头两次 |
| 同意 | 同意、表示同意 | `CMD_GIMBAL_AGREE` | 点头一次 |
| 不同意 | 不同意、拒绝、表示拒绝 | `CMD_GIMBAL_DISAGREE` | 摇头一次 |

语义别名共用同一个线协议命令 ID：同意 = 点头，不同意 = 摇头，打招呼 = 连续点头两次。这样不会为相同动作重复占用协议编号。

## 2. 命令 ID

保留现有底盘命令编号，不改变旧协议：

| 命令 | ID |
|---|---:|
| 停止 | `0x01` |
| 前进 | `0x02` |
| 后退 | `0x03` |
| 左转 | `0x04` |
| 右转 | `0x05` |
| 点头 | `0x16` |
| 摇头 | `0x17` |
| 连续点头 | `0x18` |
| 连续摇头 | `0x19` |
| 头部中立动作 | `0x1A` |

六字节帧格式仍为 `AA 55 CMD LEN SEQ CHK`，校验规则沿用现有 `CMD XOR LEN XOR SEQ`。本次不改变帧长度、帧头或旧命令 ID。

## 3. 调度与安全规则

1. `CMD_STOP` 优先级最高；收到后清除尚未发送的底盘运动命令。
2. STOP 尚未发送成功或仍处于发送中时，拒绝新的底盘运动命令。
3. STOP 不清除已经排队的头部表情动作；底盘与头部动作属于不同执行通道。
4. 底盘运动命令和云台/表情命令使用独立待发送槽位，互不覆盖；同一通道连续收到多个命令时保留最新一个。
5. 串口每次仍发送一帧。STM32 收到后必须把底盘运动和舵机动作交给各自的非阻塞状态机，不能用延时循环等待一个表情动作结束，否则会阻塞另一通道。
6. 语音识别必须按完整短语或意图归一化，不能简单做子串匹配。例如“不要前进”不得被误识别为“前进”。意图不确定时不执行运动命令。

## 4. 舵机动作语义

- `NOD`：Pitch 从中位向下偏转，再回到中位。
- `SHAKE`：Yaw 短时向左、再向右，最后停止。
- `NOD_TWICE` / `SHAKE_TWICE`：重复对应动作两次。
- `NEUTRAL`：停止连续旋转 Yaw，并将 Pitch 目标设为中位。

**硬件限制：** 当前 Yaw 使用 360°连续旋转舵机且没有角度反馈。它只能控制转向、速度和持续时间，不能精确指定角度。因此 `NEUTRAL` 只能停止 Yaw 并让 Pitch 回中，不能保证头部 Yaw 朝向机械正前方。要实现真正的左右角度定位和精确回正，需要位置舵机或角度反馈。

## 5. AI 对话触发

若 AI 对话层希望根据自己的回复驱动表情，应输出明确的语义事件，而不是扫描回复文本中的关键词：

- `ACK` / `AGREE` → `CMD_GIMBAL_NOD`
- `REFUSE` / `DISAGREE` → `CMD_GIMBAL_SHAKE`
- `GREETING` → `CMD_GIMBAL_GREETING`

该路径与用户直接说“点头/摇头”的语音指令共用同一套动作命令。

## 6. 当前集成边界

本次已将规范命令 ID、公共路由队列和主机单元测试写入当前 GitHub 远端的共享层快照。CI1302 的实际 word-ID 表、ESP32 语音解析入口、STM32 命令分发与舵机动作状态机尚未出现在当前远端快照中，因此本文件不虚构 word ID，也不宣称真实舵机已经执行或完成硬件验收。待完整本地固件源文件同步后，再把识别词 ID 和执行函数接入对应目标文件。
